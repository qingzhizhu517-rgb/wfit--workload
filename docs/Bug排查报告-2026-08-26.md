### 🔴 Bug #1【P1 · 功能缺陷】明细页写操作权限串未登记 — 核心数据维护链路断裂

| 项 | 内容 |
|----|------|
| **现象** | 7 张 G 明细页 + 6 个配置/业务页的「新增/修改/删除/导出」按钮对非超管不可用 |
| **影响范围** | `wlTheory / wlPractice / wlInternshipTraining / wlCourseDesign / wlThesis / wlConcentratedInternship / wlManagement` + `allowanceItem / importBatch / payRate / payRecord / workloadCategoryDict / workloadRule` |
| **复现路径** | ① admin_test 登录 → 工作量明细 G1 → 无任何操作按钮（v-hasPermi 隐藏）；② 直接 `curl -X POST /system/wlTheory -H "Authorization: Bearer <教务token>"` → 403 |
| **根因分析** | `05_biz_menu.sql` 仅登记 41 个 F 型按钮，7 张 G 明细表只有 `list`（页面菜单 C 型），**add/edit/query/remove/export 五类按钮全部未生成**。后端 `@PreAuthorize` 齐全（178 个权限串），前端 `v-hasPermi` 齐全，唯独 SQL 登记缺失 → 任何角色（除 userId=1 超管豁免）都不持有这些权限。08/09/13 补丁只补了审批/仪表盘按钮，未覆盖明细页 |
| **证据** | 后端权限串 178 个 vs SQL 登记 58 个；缺口清单见附录 A（~60 个） |
| **严重性** | 高：业务管理员与教务无法维护工作量明细、费率、规则、导入批次——核心功能对管理端失效（仅超管可用） |
| **修复方案** | 新增 `15_fix_menu_buttons.sql`：为缺失权限串登记 F 型按钮菜单（挂对应页面菜单下），并给 role2/role3 补授权（role1 由全量授权自动获得）。详见附录 B |
| **回归验证** | admin_test 登录后按钮出现；curl 携带教务 token 调用 add/edit → 200；teacher_test → 仍 403（教师本就不该有明细写权限） |

### 🟠 Bug #2【P2 · 横向越权】审批 submit/batchSubmit 无归属校验 — 教师可提交他人汇总

| 项 | 内容 |
|----|------|
| **现象** | 教师（role4）持有 `system:audit:submit`（20205），`submit(id)` 仅校验状态（必须 DRAFT），**不校验汇总归属** |
| **复现路径** | 教师 A 登录 → `POST /system/audit/submit?id=<教师B的汇总id>`（B 的汇总若处于填报中）→ 成功，B 的汇总进入审批流。`batchSubmit?ids=[]` 同理可批量提交任意人 |
| **根因分析** | 代码设计缺陷：同文件 `teacherConfirm` 用 `teacherConfirmById(id, userId)` 做了归属校验，`submit` 未对齐。approve/sign/reject 为审批角色处理全体记录属设计意图，但 submit 是「本人动作」 |
| **证据** | `BizAuditServiceImpl.submit()`（L81-90）无归属校验；`BizAuditController.submit` 权限串 `system:audit:submit` 教师持有 |
| **严重性** | 中：业务干扰（伪造提交、干扰审批流），不涉及数据读取 |
| **修复方案** | submit 中教师角色时校验归属：`DataScopeUtil.assertOwnOrAdmin(summary.getUserId())`（与 teacherConfirm 对齐） |
| **回归验证** | 教师 A token 提交 B 的汇总 → 应返回"无权访问他人数据"；提交本人 → 200 |

### 🟡 Bug #3【P3 · 死权限】`system:calc:recalc` 登记但无代码使用

## 四、知识沉淀（Bug 根因模式）

1. **「三源不一致」权限模式**：RuoYi 权限由 `后端 @PreAuthorize + 前端 v-hasPermi + SQL sys_menu.perms` 三处共同定义，任何一处漏登记即导致**过度限制（功能缺失）或越权（安全）**。排查权限问题必须三源交叉比对（本报告 Bug #1/#2 均属此类）。
2. **补丁只补热点不补全量**：08/09/13 补丁修复了审批/仪表盘权限，但未系统核对全量权限登记——修复类补丁应配套全量比对脚本。
3. **归属校验一致性**：同一状态机内「本人动作」（submit/teacherConfirm）都应做归属校验；审批动作（approve/sign）豁免。代码审查应检查这类"同类不同规"。
4. **死权限是架构腐化信号**：登记了无人使用的权限串会误导后续维护者（system:calc:* 被误认为存在 calc 权限体系）。
