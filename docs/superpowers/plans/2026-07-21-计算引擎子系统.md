## 关键设计决策

1. **公式与舍入**：BigDecimal 全程，中间不截断，最终 `setScale(2, HALF_UP)`。常数/档位一律走 `RuleParamService`，不硬编码。
2. **冻结护栏**：7 个明细 ServiceImpl 的 insert/update/delete 前查父 item，`status==1(已核对)` 抛 `ServiceException("已核对，系数已冻结")`；成功后调 `recalcItem` 回写 `calculated_workload`。G8/G9 无明细表，item 直录金额不重算。
3. **汇总口径**：聚合 `status!=3(已驳回)` 的全部明细（含未核对，便于预览；返回值附带未核对条数）。G11 合计 `min(sum, CAP_G11_SEMESTER=180)`。`excess=max(0,total−180)`；绩效：专任 `(min(total,540)−180)×rate`，下限 0，`total>540 → is_capped=1`；非专任（外聘等）绩效=0。title/pay_rate 快照自 teacher_profile + biz_pay_rate 当期生效行。
4. **达标**：年标准(教授128/副240/讲师240/助教192)÷2 → 产假×0.5、在职读博→64、访学→视同完成(met=1)；`met = G10 ≥ standard`。
5. **其他酬金 A~G**：新费率入规则表（种子 SQL）：B 分散10/集中15 每人、C 120/人、E 60/时、F (天×6+班×1)×30、G 工作量×30、A 自学辅导 <6人120/6-20人260；**A 跟班/单独开班首期=手工金额**（策略原样返回，TODO 待正式文件）；D 停用。allowance_item 增删改后自动重算 amount。
6. **G11 生成器**：`SemesterCalendar` 从 yml 读校历（默认 秋 09-01~01-31 / 春 02-20~07-15），`prorated = allowance_rate/2 × overlapDays/semesterDays`；`end_date NULL`=学期末。按 assignment 幂等生成/更新 G11 item+明细。
7. **触发方式**：明细 CUD 自动重算单条；汇总/酬金/G11生成走显式 API（后续审批流复用同 service）。
8. **前端本阶段不动**——纯 API 验证；按钮留给教师端 UI 阶段。
