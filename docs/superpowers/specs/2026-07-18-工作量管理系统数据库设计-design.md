# 潍理工工作量管理系统 - 数据库设计（重构 v2）

- **日期**：2026-07-18
- **阶段**：初期设计 / 数据库表设计
- **框架**：若依前后端分离（Spring Boot + Vue，复用 sys_user / sys_role / sys_dept / sys_dict / BaseEntity / sys_oper_log）
- **依据**：
  - 《潍坊理工学院教师工作量管理办法（2026 年 3 月修订·征集意见稿）》（下称 PDF，权威）
  - 附件1《教师教育教学工作量统计表》（表一，老师实际填写的工作量表）
  - 附件2《教师教育教学工作量绩效酬金统计表》（表二，酬金表）
- **v1 说明**：旧版数据库设计（8 表）已废弃，仅作参考。本设计以 PDF + 附件1/2 为准重新建模。

---

## 1. 目标与范围

**核心目标**：用系统**自动汇总**替代老师手动汇总、核对、填写工作量。提供教师 Web 端口，老师只需做**部分手动选择与核对**（边缘项目录入 + 系数确认）。

**首期范围**：
- 教学工作量计算（G1～G9）+ 管理服务工作量（G11）+ 学期汇总 + 绩效酬金。
- **只做专任教师**（含双肩挑）的绩效酬金；**外聘/校企/银龄首期不纳入统计**（教师档案保留 `teacher_nature` 字段以备后续）。
- 主聚合单位为**学期**（如 `2025-2026-1`）；学年用于「达标」展示。
- 数据进出：教务处 Excel 导入（教学任务/教师信息/岗位任职 3 模板）+ 附件1/附件2 仿真预览导出。

**不在首期范围**：外聘酬金计算、与评价系统/课程库的自动对接（系数先用「基础值预填 + 老师可改」过渡）。

## 2. 设计锚点（已确认决策）

| 决策 | 结论 |
|---|---|
| 数据边界 | 教务处导出 Excel -> 本系统 Excel 导入（教学任务/教师信息/岗位任职 3 模板）+ 手动补充（毕设/实习/课程设计/讲座/值班等） |
| 数据导出 | 附件1/附件2 格式 Excel，导出前仿真预览（1:1 还原版式） |
| 实体结构 | 混合：明细主表 `biz_workload_item` + 类别明细表（1:1） |
| 系数模型 | 所有系数给「基础值」（有数据源自动推断、无源用规则默认），老师始终可在 Web 端修改；明细「已核对」后冻结 |
| 额定工作量 | 统一 180/学期（PDF 第二十条绩效口径）。附件1 的「文科/理工科」是 G5 毕业论文 K5 的分档列，非额定分档 |
| 特殊状态 | 只折算「达标」（产假 50%、在职读博 128/年、访学 >1 月视同完成），绩效额定仍统一 180 |
| 绩效酬金 | 专任 `(min(总工作量,540) − 180) × 职称单位酬金`；200% 封顶（总工作量 ≤ 540 全计） |
| 管理服务 G11 | 与教学一致的「源(岗位任职) → 明细」模式 |
| 酬金 A～G | 单表 `biz_allowance_item` + JSON ext + fee_type 策略 bean |
| 代阅卷 D | 预留 `fee_type=D` 结构，首期不启用，待正式文件后填值启用 |

## 3. 分层架构与数据流

```
源数据层              计算明细层                   汇总层            酬金层
biz_teaching_task  ─┐
(导入教学任务)       ├──► biz_workload_item ────► biz_workload ──► biz_pay_record
biz_role_assignment┘     (主表) + G1~G6/G11        _summary        (酬金汇总)
(岗位任职)               类别明细表(1:1)                            ▲
                                                                biz_allowance_item
支撑: biz_workload_category_dict / biz_workload_rule / biz_pay_rate / biz_import_batch（biz_teacher_profile 亦 Excel 导入，见 5.6）
```

**数据流**：
1. 教务处导出 Excel，本系统按模板 Excel 导入（教学任务/教师信息/岗位任职，`biz_import_batch` 记批次） → 生成 `biz_workload_item`（type=G1/G2…）+ 对应类别明细，系数按基础值预填。
2. 手动项目（毕设/实习/课程设计/讲座/值班等）由老师/院部在 Web 端录入 → 写入 `biz_workload_item` + 类别明细。
3. 管理服务：院部维护岗位任职 `biz_role_assignment` → 生成 G11 明细（按任职区间折算）。
4. 老师核对明细、可改系数 → `biz_workload_item.status=已核对` 后系数冻结。
5. 汇总服务计算 G7→G10→总工作量→超额定→绩效酬金，写入 `biz_workload_summary`。
6. 酬金服务算课时酬金（绩效）+ 其他酬金（A～G），写入 `biz_pay_record` + `biz_allowance_item`。
7. 两级审核：明细级（超标审批/申诉）+ 汇总级（教师签字→院部公示→教务审核→锁定）。

#### 5.2.2 biz_wl_theory（G1 理论课明细）
公式：`G1 = J1 × C1 × K1 × Q1 × Q2 × Q3 × N`

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| item_id | BIGINT | PK, FK biz_workload_item.id | |
| J1 | DECIMAL(10,2) | NOT NULL | 理论课学时数 |
| C1 | DECIMAL(10,2) | DEFAULT 1.00 | 重复系数：1.0 / 0.9 / 0.8 |
| K1 | DECIMAL(10,2) | DEFAULT 1.10 | 课程类型：必修 1.1 / 选修 1.0 |
| Q1 | DECIMAL(10,2) | DEFAULT 1.00 | 教学质量：优秀/良好/合格 1.0，不合格 0.8 |
| Q2 | DECIMAL(10,2) | DEFAULT 1.00 | 课程质量：省级一流主持 1.5/团队 1.2；校级主持 1.2/团队 1.1；其他 1.0 |
| Q3 | DECIMAL(10,2) | DEFAULT 1.00 | 全外文系数（按外部门文件，待定） |
| N | DECIMAL(10,2) | DEFAULT 1.00 | 合堂：120-150 → 1.1，≥151 → 1.2 |

#### 5.2.3 biz_wl_practice（G2 课内实践/实验/实训明细）
公式：`G2 = J2 × K × C2 × Q1 × Q2 × Q3`

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| item_id | BIGINT | PK, FK | |
| J2 | DECIMAL(10,2) | NOT NULL | 实践课学时数 |
| K | DECIMAL(10,2) | DEFAULT 1.00 | 实践课程系数：理工 1.0 / 其他 0.9 |
| C2 | DECIMAL(10,2) | DEFAULT 1.00 | 实践重复系数：第一次 1.0，第二次起 0.9 |
| Q1 / Q2 / Q3 | DECIMAL(10,2) | DEFAULT 1.00 | 同 G1 |

#### 5.2.4 biz_wl_internship_training（G3 教学实习/实训明细）
公式：`G3 = T × D × K × Q1 × Q2 × Q3`

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| item_id | BIGINT | PK, FK | |
| T | DECIMAL(10,2) | NOT NULL | 实际天数（1 天=8 学时，四舍五入 1 位） |
| D | DECIMAL(10,2) | NOT NULL | 指导系数：理工 4.0 / 艺术 3.0 / 文史 2.0 / 单位指导 2.0 |
| K | DECIMAL(10,2) | DEFAULT 1.00 | 重复系数：第一轮 1.0，第二轮起 0.9 |
| Q1 / Q2 / Q3 | DECIMAL(10,2) | DEFAULT 1.00 | |

#### 5.2.5 biz_wl_course_design（G4 课程设计明细）
公式：`G4 = J4 × R4 × 0.4`，R4 ≤ 20，超出不计。

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| item_id | BIGINT | PK, FK | |
| J4 | DECIMAL(10,2) | NOT NULL | 课程设计计划学分 |
| R4 | INT | NOT NULL | 指导人数（≤20，超出不计） |

#### 5.2.6 biz_wl_thesis（G5 毕业论文明细）
公式：`G5 = R5 × K5`。

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| item_id | BIGINT | PK, FK | |
| R5 | INT | NOT NULL | 指导人数；本科 ≤10（>8 须院长批），专科 ≤15（>15 须院长批） |
| K5 | DECIMAL(10,2) | NOT NULL | 系数：理工类本 9 / 专 5；文史类本 6 / 专 4 |
| education_level | VARCHAR(20) | | 本/专（决定 K5 档与 R5 上限） |
| major | VARCHAR(50) | | 理工类/文史类（决定 K5；艺术类映射待确认） |

> G5 文科/理工分档即由此表的 `major + education_level → K5` 体现（附件1 的文科/理工科列即指此）。

#### 5.2.7 biz_wl_concentrated_internship（G6 集中实习-现场跟班明细）
公式：`G6 = W × R6 × 0.4`，R6 ≤ 20，超出不计。

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|

| W | DECIMAL(10,2) | NOT NULL | 实习周数 |

#### 5.2.8 biz_wl_management（G11 管理服务明细）
由 `biz_role_assignment` 生成。多岗叠加、学期封顶 180 由汇总服务处理。

- **B 毕业实习**：分散 10 元/人；集中（不现场跟班）15 元/人。（集中现场跟班是 G6 工作量，不在 B）
- **C 论文重修**：120 元/人。
- **D 代阅卷**：按人数档位（首期停用，待正式文件）。
- **E 讲座**：时长 × 60 元/小时。
- **F 运动会裁判**：每天 6 工作量 + 每体测班 1 工作量，× 30 元/单位。
- **G 夜间值班**：工作量 × 30 元/单位（以签字为据）。

## 6. 关键计算逻辑

### 6.1 系数推断与冻结
- **预填基础值**：导入/录入明细时，按数据源自动推断（排课 → N/C1、课程库 → Q2、评价系统 → Q1、全外文标志 → Q3；首期无源则用规则默认值 Q1=1.0、Q2=1.0、Q3=1.0、C1=1.0…）。
- **老师可改**：所有系数在 Web 端可修改；"改了哪些"由若依 `sys_oper_log` 审计，不在表内冗余 base/final。
- **冻结**：`biz_workload_item.status=已核对` 后系数冻结；`biz_workload_summary.status=已锁定` 后整张汇总不可改。

### 6.2 汇总公式
- G7 = G1+G2+G3+G4+G5+G6
- G10 = G7+G8+G9
- 总工作量 = G10 + G11
- 超额定 = max(0, 总工作量 − 180)

### 6.3 绩效酬金（专任）
- `performance_pay = (min(总工作量, 540) − 180) × 单位酬金(按职称)`
- 总工作量 ≤ 180 → 0；180 < 总 ≤ 540 → (总−180)×rate；总 > 540 → 360×rate，且 `is_capped=1`。
- 单位酬金：教授 70 / 副教授 60 / 讲师 50 / 助教 40（取 `biz_pay_rate` 当期生效值，快照入 summary）。

### 6.4 达标（第五条，展示用，不进绩效）
- `basic_teaching_standard` = 按职称年度基本教学量折算到学期，再按特殊状态折算：
  - 正常：教授 128/副教授 240/讲师 240/助教 192（/学年 → /2 学期）
  - 产假：×0.5
  - 在职读博：128/学年
  - 访学 >1 月且考核合格：视同完成
- `basic_teaching_met` = (G10 ≥ basic_teaching_standard) ? 1 : 0

### 6.5 管理服务 G11
- 由 `biz_role_assignment` 生成：标准学时/学年 × (本学期任职天数 / 学期天数) → `prorated_amount`。
- 多岗叠加；**学期累计封顶 180**（超出部分不计）。

## 7. 审核流程（两级）

**明细级**（`biz_workload_item.status` + 超标/申诉字段）：
- 老师核对 → `已核对`（冻结系数）。
- G5 毕设 R5 超标（本科 >8、专科 >15）、G6 实习超标 → `is_over_limit=1`，触发院长审批（`dean_approval_status`）。
- 申诉 per 项：`appeal_status` 流转（申诉中→已处理/已驳回）。

**汇总级**（`biz_workload_summary.status`）：
- 草稿 → 已公示（院部公示）→ 已审核（教务助理 + 院部领导签字）→ 已锁定。
- 提交审核的前置：该教师本学期所有明细 `status=已核对`，且无未决超标审批/申诉。

附件2 酬金 `biz_pay_record` 跟随汇总状态：汇总锁定后酬金定稿。

## 8. 完整性约束与校验

- **类别上限**：G4 R4 ≤ 20、G6 R6 ≤ 20；超出部分不计（服务层截断）。G5 R5 本科 ≤10（>8 须院长批）、专科 ≤15（>15 须院长批）。
- **系数范围**：各系数列 DB CHECK 或服务层校验（如 N ∈ {1.0,1.1,1.2}，Q1 ∈ {1.0,0.8}）。
- **快照不可变**：`summary.status=已锁定` 后，对应明细与汇总行只读（应用层 + 触发器/拦截）。
- **唯一性**：`(user_id, semester)` 在 summary、pay_record 唯一；`(rule_code, effective_from)` 在 rule 唯一。
- **外键**：明细 `item_id → workload_item.id`（1:1）；`task_id → teaching_task.id`；`assignment_id → role_assignment.id`；`summary_id → workload_summary.id`；`pay_record_id → pay_record.id`。
