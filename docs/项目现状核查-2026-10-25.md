## 3. 架构与模块

这是基于RuoYi-Vue3的前后端分离、Maven多模块单体系统。

| 模块 | 职责与主要内容 |
|---|---|
| `front/RuoYi-Vue3` | Vue3.5、Vite6、Element Plus、Pinia；系统管理、教师工作台、教务工作台、业务CRUD、因子详情、申报、核算和导出 |
| `rear/workload-admin` | 启动入口、配置、系统管理Controller；后端默认8084 |
| `rear/workload-framework` | Spring Security/JWT、数据源、AOP、MyBatis配置、强制改密拦截 |
| `rear/workload-system` | 核心业务；Controller → Service → Mapper/XML；calc内为策略、规则、核算编排、汇总、酬金和冻结保护 |
| `rear/workload-common` | BaseEntity、AjaxResult/TableDataInfo、Redis封装、权限辅助、日志注解、Excel等公共能力 |
| `rear/sql` | 手工编号的结构、种子、菜单权限及升级补丁；当前未接自动迁移 |
| `docs` / `else` | 实施计划、审查、操作说明、需求及制度依据；部分记录过时 |

本地业务包有23个REST Controller，测试目录有38个Java类（含1个显式运行的MySQL IT）。不能沿用“只有两个策略测试”的旧说明。quartz、generator、Vue2前端已从应用模块移除；数据库仍保留部分历史框架表，表存在不表示模块仍运行。

前端开发端口3000，`/dev-api`去前缀代理至8084。MySQL保存业务持久数据，Redis承载登录会话、配置及规则缓存。后端凭据从环境变量或被忽略的`.env`注入。

### 业务数据分层

1. 支撑：教师档案、类别字典、工作量规则、费率、导入批次。
2. 源数据：教学任务、教师学期岗位减免（兼容表`biz_role_assignment`）。
3. 计算明细：`biz_workload_item` + G类子表；快照表、系数调整申请提供追溯与变更审批。
4. 汇总：`biz_workload_summary`保存G7—G11、总量、超额、绩效等。没有设计稿中的`category_details`字段。
5. 酬金：`biz_allowance_item`记录A—G其他酬金；`biz_pay_record`汇总课时绩效与其他酬金。
6. 审批：`biz_audit_log`记录汇总动作；目标中的独立明细审核批次和线下补差域尚未落地。

### 核心业务与口径

- G1—G6由策略计算，类别字典保存Spring Bean名，由`CalcStrategyFactory`分发；G8/G9手工录入；G7/G10是合计，不是独立计算策略。
- G11直接同步教务核定的本学期岗位减免值，合计计入汇总时按180封顶；岗位名称不触发再次折算，教师不能自由申报最终G11。
- 当前G1/G2/G3不乘Q3；G4按实际人数计算，超过60仅告警；G6人数按20封顶。README仍有旧公式，验收期望应取当前策略与已确认口径。
- 汇总计算G7→G10→总量；超额展示和绩效封顶口径不同；绩效使用540等规则参数及人员性质、职称费率。其他酬金按A—G策略处理，不能全部简化为单一课时单价。
- `WorkloadCalcService.run/runBatch`按教师、学期编排校验→G11→明细→汇总→酬金，返回阶段回执；批量按教师隔离事务。
- 快照保存公式、因子、来源、结果、版本、哈希；本地增量新增解释上下文。历史详情优先读快照，无快照标记legacy。

### 两套状态机

| 对象 | 含义 |
|---|---|
| 汇总status | 0草稿 → 1教务待审 → 2完结；驳回1→0；完结永久锁定 |
| 明细status | 0草稿、1已核对、2有异议、3已驳回；与汇总状态独立 |

本地增量在汇总提交和通过前检查待审系数与未核对明细；明细核对带版本和学时检查。这是已有的最小核对能力，不等同于计划中的分类审核中心。
