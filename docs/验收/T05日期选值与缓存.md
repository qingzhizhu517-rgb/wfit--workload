# T05 第一切片：按学期结束日选值与缓存（2026-10-29）

本切片实现并验证通过。T05整体仍在进行中：尚无不可变政策来源、快照完整性/旧哈希兼容、汇总/酬金结算证据和异常人员资格收口，不能宣称历史重算已可完整复现。

## 实现

沿用需求默认“按学期结束日选择当时有效规则和费率”。生产调用显式传入`SemesterCalendar.endOf(semester)`，使用`wl.semester`配置；标准旧学期格式不变，拒绝非法期次、不连续学年、结束早于开始的校历。

覆盖G4/G5/G6策略及回调、导入派生系数、新鲜公式、汇总和基本教学标准、A—G其他酬金、汇总列表逐行封顶、Dashboard及附件2。保留旧无日期API供兼容，生产核算调用均迁入日期API。既有G1/G2/G3/G5已物化的来源系数未被伪造为可追溯政策版本。

规则和费率的有效区间包含首尾日；多版本取最近生效日，同一个最近起始日有多个有效版本则拒绝歧义，不依赖数据库返回顺序。无历史费率时返回null，不套用当前费率；缺失规则的既有默认值行为保留，默认常量的不可变版本归属仍需下一切片处理。

规则缓存包含编码、日期和世代；规则CRUD在事务成功提交后更换新旧编码世代，覆盖全部日期。事务内读绕开共享缓存，回滚不驱逐；旧在途回填留在旧世代，24小时TTL回收。更新、单删及批删通过`FOR UPDATE`当前读获取真实旧编码，XML的`flushCache=true`清理MyBatis会话缓存；批删复制、去重并排序ID后加锁。字典增改删成功提交后驱逐StrategyCache，包括原先缓存的null策略和策略改绑。

费率原本不缓存，本次未额外引入缓存。StrategyCache仍是单进程缓存，多实例广播失效需后续另行验证，不把本地失效视为分布式证明。

## 日期契约及审查修复

真实HTTP复现日期选择器提交`yyyy-MM-dd`时，旧后端按全局`yyyy-MM-dd HH:mm:ss`反序列化有效期失败。最初字段级格式修复又在独立质量审查中暴露时区偏移：Tokyo JVM下，SQL DATE `2026-01-01～2026-01-31`经HTTP变为`2025-12-31～2026-01-30`，已用真实MySQL/HTTP红测确认。

最终将规则和费率的四个有效日期字段、访问器与resolver统一为LocalDate；GET筛选显式ISO.DATE，JSON仍为yyyy-MM-dd；MyBatis使用内建LocalDateTypeHandler直接读写SQL DATE，不再经过毫秒或默认JVM时区。创建、更新时间仍按原Date处理。数据库列不变，无DDL或迁移。本次仅为Jackson3实际契约测试补test-scope databind依赖，运行时依赖不变。

规格复核与质量复核均通过。时区P2在代码修复、四时区回归以及Tokyo/UTC真实HTTP复核后闭环，未靠更改全局时区或放宽测试规避。
