# 工作量核对、审核批次与线下补差契约

状态：T07后端生命周期/API已完成隔离技术验收，见T07审核生命周期.md；T08页面尚未接入。不能把迁移成功解释成审核业务验收。权威路线图为`docs/superpowers/plans/2026-10-25-project-roadmap.md`，本契约替代旧审核中心计划中的冲突口径。

## 两个阶段与授权

| 阶段 | 对象及状态 | 名称、权限 | 作用 |
|---|---|---|---|
| 提交前 | summary.status=0，item.status=0/1/2/3 | 教务核对；`system:workloadItem:review` | 校验草稿明细，独立于审批证据 |
| 提交后 | summary.status=1，当前审核批次 | 待审逐条审核；`system:auditRecord:review` | 对已冻结明细证据作出PASS/REJECT结果 |
| 授权例外 | 同上 | 审核豁免；`system:auditRecord:waive` | 单独最小权限，不能以普通review替代 |
| 完结后 | summary.status=2永久锁定 | 线下说明；`system:offlineAdjustmentNote:add` | 仅追加线下补差说明 |

summary状态仍为0填报中→1教务待审→2已完结；驳回1→0必须给出非空原因并清签。2不得解锁。item.status仍为0草稿/1已核对/2有异议/3已驳回，绝不存储PASS等审核结果。教师确认仍是独立签字动作。

预置六个权限均为汇总菜单2020下的隐藏F按钮（visible=1、status=0、component=NULL、path空），没有新增C菜单或`system/auditCenter/index`路由。menu_id按perms探测后由数据库分配，禁止硬编码2023或其他未核实空闲ID。角色按key授予，不依赖测试角色ID：

| 权限 | admin / biz_admin | jiaowu / assistant | teacher / leader / 其它 |
|---|---|---|---|
| auditRecord:list/query/review | 是 | 是 | 否 |
| auditRecord:waive | 是 | 否 | 否 |
| offlineAdjustmentNote:query | 是 | 是 | 否 |
| offlineAdjustmentNote:add | 是 | 否 | 否 |

以上权限均带`system:`前缀。教师通过本人summary详情下的受控分页端点读取本人审核/时间线/补差说明，复用`system:workloadSummary:query`且强制用户范围，不能获得审核中心或写权限。框架超级管理员通配权限仍存在；T07必须显式保护写动作、用户范围与状态。权限预置不代表API已开放。

## 数据版本和不可变批次

`biz_workload_summary`新增`data_version BIGINT NOT NULL DEFAULT 0`、`review_batch_no VARCHAR(50) NULL`、`last_calculated_at DATETIME NULL`。0和NULL只表示未纳入新版审核，不是“历史已核算版本”或历史核算时间。35不回填旧待审/完结记录，也不从当前规则生成历史证据。

T07在锁定教师学期、summary、明细/酬金后，每次成功持久化新版汇总/结算（含只重算其他酬金导致的新结算）在同一事务递增data_version；真正重算汇总才记录last_calculated_at。标脏仍用needs_recalculation，不能仅凭版本相同越过新鲜度门禁。待审/完结期间不允许改变任何已审核业务值。T06仅提供列；T07现已实现写入口版本推进、失效约束和提交门禁，历史版本0必须先重算。

`biz_workload_review_batch`固定一份提交证据，唯一键`(summary_id,review_batch_no)`；批次号为服务端不透明唯一值，客户端不能指定。字段：id、summary_id、review_batch_no、summary_data_version、user_id、semester、settlement_snapshot_id、settlement_snapshot_hash、format_version、snapshot_json、data_hash、created_by、created_at。summary_data_version必须>0。batch只INSERT/SELECT，不UPDATE/DELETE。

提交时服务端保存format_version=1的规范化snapshot_json，至少固定：summary身份/数值/人员与签字、dataVersion、新鲜度及计算时间；纳入审核的itemId有序全集、逐项calculationVersion/已有计算snapshotId/hash、来源引用与缺失标记；T05结算snapshotId/hash。data_hash用确定顺序/数值字符串/显式NULL的canonical SHA-256，不能直接对数据库JSON展示文本哈希。T07实现独立codec和完整性校验，不复用T05明细或结算format编号。批次中签字是提交时已存在签字的快照；随后合法teacherConfirm属于已有独立签字动作，只追加签字及独立审计日志，不能重写批次JSON，也不改变计算data_version。终审应分别校验保存批次hash、当前计算版本/成员与既有签字合法性，禁止用当前签字重新拼接旧hash。原流程未要求教师先签字才能终审，本次不新增该业务门槛；teacherConfirm仍按本人待审动作记录。

T05引用存在时必须读取并验证原结算证据，其id/hash成对保存，禁止另取当前人员/费率/规则解释历史。不存在时两列均NULL，snapshot中明确HISTORICAL_MISSING；不能伪装完整证据或绕过T05资格门禁。不得回写旧format4因子JSON、结算快照及summary/pay指针。hash只能检查内容一致性，不能宣称抵抗数据库管理员重签。

## 逐条审核记录

`biz_workload_item_review`目标仅为`biz_workload_item`；不允许target_type/target_id或ALLOWANCE。字段：id、summary_id、item_id、review_batch_no、review_type、format_version、snapshot_json、data_hash、result、reason、reviewer_id/name、reviewed_at、version、create_by/time、update_by/time。唯一键`(summary_id,review_batch_no,item_id)`保证每批每明细一条；T07锁内验证item属于summary的教师/学期、batch存在及成员全集一致。本项目不新增外键，故这些关联约束必须由T07事务和测试落实。

分类优先级固定`OVER_LIMIT > G11_ROLE > MANUAL_DECLARATION > TEACHING_TASK`：is_over_limit=1优先；其后G11；其后source_type为SELF或MANUAL；其余有教学任务来源的明细。没有可解释来源的记录提交时拒绝，不静默归类。其他酬金保持T05独立结算证据，本期不作多态逐条审核。

format_version=1的item快照保存item身份、来源类型/id、项目/类别、实际核定工作量、异常、calculationVersion、已有计算快照与hash、T05实际因子/手工来源证据或HISTORICAL_MISSING标记。证据列、summary/item/batch引用和review_type写入后不可改；只有结果列和update审计允许CAS更新。

result仅`PENDING/PASS/REJECT/WAIVE`，初值PENDING，version初值0。REJECT与WAIVE均要求trim后非空原因，最多500字符；PASS原因可空。T07审核命令仅接受`version/reason`及动作，拒绝伪造reviewer、operator或审计时间。写入条件同时包含summary状态1、当前批次、匹配summary_data_version、原result=PENDING、原version匹配；成功version+1，服务器写审核人/时间。终态记录不再改审；需要改正则驳回汇总、修改草稿、重新提交新批次。过期/重复/跨批命令返回409，不留下部分变更。

终审要求当前batch确实存在、成员完整且非空、数据版本与证据hash匹配、新鲜度与T05结算门禁满足，所有记录PASS/WAIVE；禁止用空集合或单纯PENDING=0作为通过。驳回保留所有历史batch/review；summary的review_batch_no可指向上次提交以便展示，只有下一次合法提交替换它，草稿不允许审核旧批次。无批次的历史待审/完结明确显示缺失；T07启用前必须定义历史待审单独处理策略，不能伪补PASS或自动放行。

## 线下补差说明

`biz_offline_adjustment_note`字段：id、summary_id、user_id、semester、request_key、adjustment_amount DECIMAL(12,2)、reason、handled_at DATE、handled_by_id、handled_by、reference_no、note_text、attachment_ref、settlement_snapshot_id/hash、created_by、created_at。user_id/semester从完结summary服务端派生，补差金额必填可正可负；handled_at记录实际线下处理日期，与created_at写入时间区分。handled_by_id/handled_by由可信登录经办人服务端写入，客户端不得伪造。reference_no可空≤100字符。唯一`(summary_id,request_key)`支持幂等追加；同key不同内容返回409。reason必填≤500字符，note_text为可选备注且T07限制≤10000字符，attachment_ref≤500且仅受控附件引用，不接受任意文件路径。

只INSERT/SELECT，无修改/删除端点或Mapper。T07持有原summary锁验证状态2、读取原结算引用（缺史保持NULL）；新增一行不修改原工作量、酬金、签字、审核/结算证据或指针，不触发重新核算、不产生财务支付。结构化保存补差金额供线下追溯，不能汇入原pay_record或summary，也不代表新增线上支付。写入前后原相关行hash必须相同；旧说明更正只能另追加说明并在文本中指明前条编号。

## 查询、并发与事务（T07责任）

详情主体仅单对象与有界聚合；reviews、auditLogs、offlineAdjustmentNotes分别返回TableDataInfo(rows,total)，独立分页，默认1/10，pageSize最大100，pageNum≥1；非法值返回400，不能降级成无分页。筛选参数白名单，排序稳定带id，不接受原样SQL片段。

按教师学期period→summary→items/allowance→pay→batch/reviews的既有锁序补齐；新批次INSERT、全部item证据INSERT、summary 0→1及审批日志必须同事务，失败全回滚。审核结果使用条件UPDATE，等待锁后读取当前版本。批量命令最多100条、禁止重复ID，每项独立事务并明确successCount/failCount/failDetails，不能在父事务自调用绕过代理。终审必须在锁内验证当前批次完整性。驳回通过同一教师学期锁及汇总当前读、待审状态CAS退回草稿，保留全部原批次与审核结果，不批准或重写证据；历史缺批次、证据损坏或版本失效也允许授权驳回，以便重新核算、重新提交。逐项审核共享该锁，不能在驳回后继续写旧批次。

## 统一审计的覆盖边界

审计四字段仅约定的BaseEntity业务实体和BizAuditLog，明确实体/Mapper statement名单，不以所有biz_或任意Map匹配。当前20个BaseEntity业务Mapper（含导入行、系数申请、七类wl明细）＋AuditLog由下一Java切片逐项列出检查。INSERT只给新行服务端create/update字段；UPDATE仅服务器update字段。参数支持名单内实体、受控Map/ParamMap、集合和数组，identity防环；保留_audit*标量只注入约定statement，不污染任意Map。

所有普通UPDATE XML必须移除create_by/create_time赋值：仅覆盖Java对象update字段不足以防止客户端伪写创建历史。禁用或忽略客户端审计属性；已有create字段（包括NULL）保持原样。业务operator/reviewer由登录用户或显式SYSTEM业务上下文产生，不能从HTTP传值或可继承线程残留取；匿名系统任务有明确SYSTEM来源，异常退出必须清理上下文。测试包含Mapper直调、集合/标量、伪造字段、异常及线程复用。

35只对`biz_audit_log`补`create_by VARCHAR(64) NULL`、`update_by VARCHAR(64) NULL`、`update_time DATETIME NULL`；已有create_time、operator_id/name原样保留。其它现有biz表不补列、不做MIGRATION/NOW回填、不收紧历史可空性。

明确排除：biz_workload_calc_snapshot、biz_workload_settlement_snapshot（固定created_by/created_at）、biz_workload_period_lock；新batch/线下说明的created_*由T07专用写路径填；item_review仅结果CAS写update字段。不得通用覆盖因子/来源JSON、业务reviewed_at、签字/锁定/导入确认/生效日期或last_calculated_at，不得破坏手工固定的历史审计时间。T05正式启用范围仍为空。
