## 二

**全局统筹层：教务处**

**职能：** 系统的最高管理员，负责制定全校宏观的核算标准与底层数据接口维护 。

**动作：** 终审全校工作量数据，导出宏观统计报表，为教学资源调配和绩效考核提供决策依据 。

**二级管理层：学院**

**职能：** 业务核心管理节点，结合本院专业特色进行差异化管理。

**动作：** 在教务处允许的范围内微调特定专业课、实验课的核算系数 ；负责本院系教师日常调代课的记录更新与工作量初审。

**协同管理层：书院**

**职能：** 聚焦学生综合素质培养与第二课堂。

**动作：** 负责对任课老师或辅导员在书院开展的辅导课、讲座、创新创业指导等实践类工作量进行认定和数据上报。

**终端感知层：任课老师**

**职能：** 系统的最终用户与服务对象。

**动作：** 登录前端界面，实时查看个人名下的课表同步情况及工作量明细 ；若对合班或代课计算有疑问，一键发起异议申请并跟踪处理进度 。



## 三

**表现层 (前端 UI/UX)：**

**技术栈：** Vue3 + Element Plus 。

**实现逻辑：** 负责构建教师端与管理员端的操作界面，实现多终端（PC/移动设备）的自适应布局，并通过 ECharts 渲染直观的图表数据 。

**业务逻辑层 (后端微服务)：**

**技术栈：** Spring Boot 框架 。

**实现逻辑：** 系统的“大脑”。封装高内聚的业务代码，重点处理复杂工作量的自动核算算法，同时负责 RBAC 用户权限拦截与异议审批流转 。

**接口层 (网关与通信)：**

**技术栈：** 标准化 RESTful API 。

**实现逻辑：** 对内连接前后端的数据交互；对外开发标准化接口，与学校现有的教务系统底层对接，实现核心排课数据的实时抓取与格式转换 。

**数据层 (存储与缓存)：**

**技术栈：** MySQL (主存储) + Redis (缓存) 。

**实现逻辑：** MySQL 负责持久化存储复杂的表结构（如教师信息、排课清单、核算规则）；Redis 用于缓存高频访问的统计看板数据，确保系统在高并发查询时响应时间 ≤2 秒 。









1.**消除数据孤岛：** 实现与学校现有教务系统的无缝对接，确保核心数据同步误差率为0 。2.**提升核算精准度与效率：** 制定贴合应用型办学特色的核算标准，实现不同学科、不同类型课程工作量的差异化自动核算，核算准确率达99.9%以上，整体管理效率提升50%以上 。3.**辅助管理决策：** 基于系统积累的真实数据形成分析报告，为教学资源配置和教师评价体系提供客观支撑，推动教学管理从“经验型”向“数据型”转变 。
